# 장소를 바꿔 이어서 작업하기

## 사무실·집에서 공통으로 사용할 것

같은 GitHub 계정과 클라우드 개발 환경에 로그인합니다. Drive는 같은 프로젝트 폴더를 사용하고 데스크톱에서는 필요한 파일을 스트리밍합니다. 클라우드에서 PC의 Drive 마운트를 사용할 수 있다고 가정하지 않습니다.

실행 중인 서버, 터미널, 미커밋 파일이 다른 세션으로 자동 이동한다고 가정하지 않습니다. 장기간 실행되는 서비스가 필요하면 별도 상시 서버를 사용하고 시작·중지 방법을 기록합니다.

## 이동 전

1. 현재 작업과 다음 할 일을 current-status.md에 기록합니다.
2. 코드와 문서 변경을 검토하고 필요한 파일만 커밋합니다.
3. 작업 브랜치를 GitHub로 push하고 성공 여부를 확인합니다.
4. 중요한 결과물을 Drive의 새 실행 폴더에 올립니다. 사용한 코드 커밋, 자료 버전, 실행 명령을 함께 보관합니다.

## 도착 후

1. 기존 클라우드 작업을 다시 엽니다. 새 환경이면 기존 체크아웃에서 원격 브랜치를 확인합니다.
2. 미저장 변경을 먼저 확인하고 git fetch origin을 실행합니다.
3. 작업 브랜치와 기록된 상태를 읽고, 안전하게 원격 변경을 가져옵니다.
4. 필요한 자료를 준비하고 python3 scripts/check_workspace.py --verify-cache로 검증합니다.

처음에는 한 작업 브랜치에서 순차적으로 진행합니다. 동시에 다른 작업을 할 때는 작업별 브랜치를 만들고 PR로 합칩니다. Drive 동기화 폴더 안에 Git 저장소를 넣어 .git을 파일 동기화하지 않습니다.

## 작업 종료 기록 양식

```text
갱신 시각 (한국 시간):
작업 브랜치 / 기준 커밋:
완료:
진행 중 / 막힌 점:
사용한 자료 ID·버전:
검증 명령 / 결과:
다음 행동 / 실행 명령:
원격 push / 결과물 업로드 여부:
```

GitHub와 Drive의 이력은 편리한 복구 수단이지만 독립 백업을 대신하지 않습니다. 중요한 원본은 별도 백업과 보존 정책을 마련합니다.
