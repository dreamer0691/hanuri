# Google Drive 자료 관리

## 권장 Drive 폴더 구조

```text
Hanuri/
  00_inbox/       # 새로 들어온 자료
  10_sources/     # 버전별 원본, 덮어쓰지 않음
  20_reference/   # 참고 문서
  30_results/    # 실행별 결과와 실행 기록
  90_archive/    # 보존 자료
```

현재 Drive 폴더는 생성하지 않았으며 접근 권한도 설정하지 않았습니다.

## 연결 전 확인

프로젝트 폴더 링크, 개인 Drive/조직 Shared Drive 여부, 읽기 또는 업로드 필요 여부를 확인합니다. 개인 계정은 사용자 OAuth, 조직에서는 관리 정책에 맞는 인증을 검토합니다. 서비스 계정은 폴더 권한과 업로드 가능 여부를 확인한 경우에만 사용합니다.

인증은 환경의 보안 설정에서 처리하며 채팅이나 Git에 값을 넣지 않습니다. OAuth refresh token은 일반 HTTP 토큰과 사용 방식이 다르므로 프록시 비밀 변수만 선언하면 동작한다고 가정하지 않습니다. 사용하는 인증 클라이언트의 지원 경로를 확인해야 합니다.

연결 구현 시 Drive API와 OAuth에 필요한 도메인만 환경 네트워크 설정에 추가하고, 작은 파일로 실제 읽기와 필요하다면 업로드를 확인합니다. 아직 다운로드·업로드·최신 목록 확인 기능은 없습니다.

## 매니페스트

data/manifest.json은 실제로 사용하는 자료만 기록합니다. 형식은 다음과 같습니다.

```json
{
  "schema_version": 1,
  "drive_folder_id": null,
  "files": [
    {
      "path": "sources/sample.csv",
      "drive_file_id": "실제 파일 ID",
      "version": "확인한 Drive 버전 또는 보존 버전 이름",
      "sha256": "64자리 소문자 SHA-256",
      "size_bytes": 123
    }
  ]
}
```

path는 .cache/data 아래의 상대 경로입니다. 원본 Google 문서·시트는 내보낸 형식과 그 결과 파일의 체크섬을 기준으로 등록합니다. SHA-256은 내려받은 파일에서 hashlib 또는 sha256sum으로 계산합니다.

Drive에서 최신 목록을 확인한 다음, 검증한 파일의 버전과 체크섬을 매니페스트에 반영합니다. 최신 버전을 무조건 기존 파일에 덮어쓰면 과거 실행을 재현할 수 없으므로 이전 원본도 보존합니다.

기본 검사는 매니페스트 형식을 확인합니다. --verify-cache는 등록된 모든 파일의 존재, 크기, SHA-256을 확인하며 누락이나 불일치가 있으면 실패합니다. 빈 목록은 자료 전송 검증을 의미하지 않습니다.
